PHASE 1 — MICROPHONE OWNERSHIP
==================================================

After P0 succeeds or existing failures are clearly documented, implement microphone ownership safely.

Create a small Koin-managed MicrophoneArbiter ONLY if the repository does not already have an equivalent abstraction.

Conceptually:

NONE
WAKE
COMMAND

Only one microphone owner may exist at a time.

The arbiter should support equivalent operations for:

acquire(owner)
release(owner)
currentOwner

Do not duplicate an existing ownership mechanism if one already exists.

Use a bounded lease for COMMAND ownership.

Recommended lease:

approximately 90 seconds

Reason:

30-second conversation window
+
possible execution/pipeline time

The lease is a safety mechanism only. It is NOT the conversation timer.

IMPORTANT:

Do not use ConversationSession.isActive as a substitute for microphone ownership.

PHASE 1A — WAKE WORD SERVICE
==================================================

Inspect WakeWordService before modifying it.

Preserve the existing Vosk implementation.

Do NOT replace Vosk.

At wake detection, ownership must transition safely:

WAKE owns microphone
→ wake phrase detected
→ COMMAND ownership acquired

Prevent duplicate microphone consumers caused by:

- ACTION_START

- recognizer restart
- service restart
- RESUME
- stale conversation state

WakeWordService must consult the microphone arbiter rather than using only ConversationSession.isActive.

SILENCE VS ERROR
==================================================

NO_SPEECH must NOT automatically terminate the conversation.

While the conversation deadline remains active:

NO_SPEECH
→ re-arm listening

Recognizer ERROR may have a separate consecutive-error limit.

Default:

3 consecutive recognizer errors.

Do not treat ordinary silence as a failed attempt that consumes the entire conversation window.

==================================================
SESSION DEADLINE TOUCHING
==================================================

Touch the conversation session when:

1. A user speech result is actually accepted.
2. TTS response actually completes.

Do NOT touch when:

- recognizer starts
- silence occurs
- recognizer errors
- TTS starts

This prevents long TTS responses from incorrectly consuming the conversation window.

==================================================
CONVERSATION EXPIRY
==================================================

When:

remainingMs() <= 0

perform:

1. Stop recognizer.
2. Release COMMAND microphone ownership.
3. Speak:
   "Standing by."
4. Resume wake detection.

Do not create a new 30-second window after every listening attempt.

==================================================
FAILED COMMANDS
==================================================

Failed or rejected commands should count as conversation turns.

They should NOT automatically terminate the conversation.

Risk rejection should normally keep the conversation open.

Only explicit interruption/termination or actual conversation expiry should end the session.
